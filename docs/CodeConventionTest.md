# 테스트 컨벤션

## 1. 테스트 메시지

### 1-1. 테스트 이름 규칙

| 상황       | 문장 형태 예시                             | 비고                         |
|----------|--------------------------------------|----------------------------|
| 정상 동작    | 시작일이면 0이다                            |                            |
| 예외 상황    | 날짜가 음수이면 생성에 실패한다                    | 가장 중요한 규칙은 앞에 배치           |
|          | 퀘스트가 비활성 상태면 진행을 시작할 수 없다            |                            |
| 경계값      | 날짜가 Int 최대값이면 정상 생성된다                |                            |
|          | 캐러밴이 0대이면 퀘스트를 수락할 수 있다              |                            |
| 상태 의존 동작 | 퀘스트가 활성화된 상태면 배달을 시작할 수 있다           |                            |
| 복합 시나리오  | 퀘스트를 선택하고 캐러밴을 배정하면 즉시 배달이 시작된다      | 여러 단계 흐름은 “A하고 B하면 C된다” 형태 |
|          | 아이템을 999개 보유한 상태에서 또 획득하면 999개로 유지된다 |                            |

---

### 1-2. 상세 규칙

* 테스트 이름 = **게임 규칙 그대로**
* 테스트 코드를 읽는 순간, 기획자·클라이언트·서버 모두 바로 이해할 수 있어야 함
* 문장 구조: **조건(입력) + 결과(출력)** → 자연스럽게 “이면”으로 연결

---

## 2. Test Template

* 테스트 한 줄 = **도메인 한 문장**
* 테스트 이름만 읽어도 규칙이 이해되어야 함

```kotlin
"시작일이면 0이다" {
}
```

### 예시

```kotlin
"시작일이면 0이다" {
}

"날짜가 음수면 생성에 실패한다" {
    shouldThrowExactly<IllegalArgumentException> {
        GameDay.of(-1)
    }.message shouldBe "날짜는 음수가 될 수 없습니다."
}
```
